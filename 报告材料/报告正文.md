# 一、需求与目标

教学场景选取上海工程技术大学图书馆的纸质图书借阅服务。目标用户是第一次借书、还书，或临时遇到续借、预约和遗失问题的本校读者。读者自然会问"这本书还能多留几天吗"或"丢了书要去哪个柜台"，而官网按服务对象、校区和业务章节组织规则。用户通常要先判断情况属于哪一类，再去查《读者手册》、核对账户状态或寻找服务点。旧版常见问题与正式手册的个别说明存在出入，例如遗失赔款的口径。该场景的价值在于缩短查找路径，并且让读者能够及时核对来源。

原型覆盖普通纸质图书的借书、还书、册数、借期、节假日归还、网上续借、续借异常、纸质图书预约、遗失处理和办理地点。项目以 2026 年 11 月 25 日核验的公开资料为依据。用户的实时借阅状态、支付金额、预约是否成功等由图书馆系统或工作人员确认。项目的直接使用结果是一份可核实的办理清单。目标包括在核验集上正确定位规则，对校区和身份不清的问法进行追问，以及在证据薄弱或超出服务范围时转介。

本项目用首位命中率和端到端成功率衡量效果。单题成功要求匹配正确规则，必要时在补充条件后给出正确分支，并在最终输出提供步骤与官方来源。无法回答的题应转介，并给出官方核实入口。项目用基于公开规则构造的问法模拟真实任务，当前数据支持评价规则检索和流程，对读者实际节省用时的评估需另行开展。

# 二、方案与系统设计

[FLOW]

规则表以 JSON 存放。每条记录包含编号、标题、用于检索的关键短语、办理步骤和可跳转的来源。规则以任务为单位切分。例如，网上续借与续借异常对应两条记录；遗失后的处理办法与校区办理地点对应两条记录。资料中的印刷页码单独记录。项目查阅了手册第 23 至 25 页以及正式借阅规则和违规处理细则，并将涉及赔付的回答限定为可核实的办理途径。口径冲突时，优先使用秋季手册及正式细则。[1][2][3][4]

规则路由有两套实现，共用同一条主流程：输入检查、范围过滤、路由、槽位追问、结果渲染。默认方案用 TF-IDF 余弦相似度排序，--router classifier 改用逻辑回归分类器。两者的差别只在"问题对应哪条规则"这一步，后续追问与出处渲染完全相同，因此可以逐题比较。分类器把"不属于借阅范围"也作为一个类别来学习，转介由模型判断，不再依赖手调的相似度阈值。

用户通过终端输入 1 到 200 个字符。程序先识别典型范围外事项，再调用路由。路由给出的规则需要读者身份或校区时，工作流检查问题里是否已包含这些条件；已有就呈现对应清单，没有就先追问。资料不足时程序给出读者服务部入口。待确认状态保存在当前会话中，用户可以回复选项、取消并重来，或直接退出；连续两次补充都没有对上选项时改为转介，不再反复追问。资料文件缺失或无法解析时，程序提示检查文件并指向馆方渠道。

# 三、机器学习方法与开源组件

项目复用了实验五中的 TF-IDF 文本表示思想，把它从关键词抽取改为检索排序。先对查询和文档做 Unicode NFKC 归一化及小写化，再在连续汉字或字母数字片段中提取长度为 2 和 3 的字符片段。例如，"网上续借"会产生"网上""上续""续借"等双字符特征。对中文直接使用短片段，保留了局部词组信息，也减少了维护分词词典的工作。标点阻断片段，避免把相邻句子误拼成词。[5]

在启动时，向量化器只在十条规则的标题和检索短语上拟合。TF 衡量某片段在一条规则中出现的次数，对正词频使用对数缩放。IDF 用平滑公式衡量片段在所有规则中的区分能力。之后将文档和用户问题转换为同一特征空间的稀疏向量，用余弦相似度排序。最高分只是词面匹配强度，可用于决定是否追问或转介。分数相同按规则编号排序。合适的替代方案包括关键词搜索和句向量检索。这里选前者作基线，以便衡量 TF-IDF 加权本身的贡献。[5][6]

为了公平比较，两种排序方法使用相同规则和字符片段。关键词基线使用 CountVectorizer 提取二值特征，再计算余弦相似度，匹配到的片段获得相同权重。主方案使用 TfidfVectorizer 的 L2 归一化与 sublinear_tf 参数，区别在于特征权重。初版直接检索，迭代版保留原问题，并对一部分常见口语追加标准业务短语。两种方法在迭代版中使用相同的扩展查询，因而可以继续比较加权贡献。[5][6][7]

## 3.1 逻辑回归路由

检索方案的问题是"该不该回答"要另设阈值。阈值在开发集上校准，换一批问法就会偏移，而且它不区分"分数低但规则对"和"分数低且规则错"。为把这一步也交给数据，项目在同一套字符片段特征上训练了一个多项逻辑回归，类目为十条规则加一个"范围外"类。

训练样本分两部分。一部分是开发集与测试集里 50 条带标注的问法，其中 38 条对应具体规则，12 条属于范围外。另一部分是规则表中已有的 78 条检索短语，每条按其所属规则打标签，相当于用领域词表做弱标注。索引只有十条规则，人工问法不足以覆盖每条规则的用语，而规则表本身就是整理过的同义表达，用它扩充训练集比另造问法更省事。范围外类由那 12 条问法示教，学到的边界用于替代固定阈值。

模型选择用三折分层交叉验证，只在人工问法上划分，规则短语固定留在训练侧，避免同一条短语同时出现在训练折和验证折造成高估。正则强度 C 在 0.3、1、3 中比较，三折准确率分别为 0.78、0.76、0.76，取 C=0.3。分类器输出各类概率，取最大者为路由结果；如果最大类就是范围外类，程序按转介处理并给出馆方核实入口。接入方式是命令行参数 --router classifier，默认仍走检索方案，便于对照。

概率只用于转介判断，没有按概率分段作答。原因是十一类问题上的概率分布偏保守，交叉验证中置信度集中在 0.1 附近，若按 0.4 一刀切会把大量正确结果也转介掉。这条限制在后续改进中列为待解决项：需要更多样本或先做概率校准，才能把置信度用于分级处理。

## 3.2 组件复用与核验

复用组件为 scikit-learn 的文本向量化、余弦相似度和逻辑回归模块。项目编写 BorrowingGuide.rank 与 RuleClassifier，将它们封装为工作流可调用的路由工具。输入为一条问题，输出为规则编号和分数（分类器另给概率）。代码在内存中构建索引与模型，调用所需权限限于读取本地规则与标注文件。安装依赖后，运行时无需访问外部服务。开源组件负责向量变换、相似度计算与线性分类，规则整理、数据结构、追问、范围判断及展示由本项目实现。[5][6][7][8]

核验时阅读了 API 说明和已安装版本的 TfidfTransformer.fit 实现，确认平滑文档频次和加一项。在三条人工构造的短文本上，单测验证了低频片段的 IDF 高于高频片段，索引外查询为零分。另测全角字符、标点、空输入、资料缺失、来源引用和校区选择。分类器部分用分层交叉验证检查准确率，并保留每折的训练与预测记录以便复核。由于索引只有十条规则，增删资料后需重新核验阈值与分类器。

以查询中的"续借"为例。设规则数为 N，包含该片段的规则数为 df，实际使用的平滑 IDF 为 log((1+N)/(1+df))+1。TF 在出现次数 f 大于零时计算为 1+log(f)，随后两项相乘。这样可以减弱重复短语的影响，并让出现在更多规则中的片段获得较低区分权重。若问题中的片段全都不在索引里，查询向量为零，正常阈值会将它转介。测试问法只执行转换，既不用于计算 IDF，也不会在每次提问后写回资料库。[5]

索引只收入标题和检索短语，办理清单、网址和电话号码通过规则编号在排序之后查询。这样做可以避免重复出现的来源词或联系电话影响排名。规则表提供随后需要的身份与校区选项，路由分数与办理资格分别由不同环节处理。

# 四、实验设计与结果

样例依据十类规则、身份和校区条件及范围外服务构造。问法覆盖常规、口语、缺少条件和邻近但不支持的服务，刻意保留空白输入以测试边界。数据为 16 条开发样例、36 条首轮测试和 24 条核验样例；标签包含期望动作、目标规则、模拟回复和正确选项，实际读者账户和咨询日志均未纳入。

需要说明核验样例的独立性问题。这 24 条虽未参与阈值计算，但个别措辞在写规则时被当作例子用过，例如核验题里的"返校再交"后来写进了口语映射，"任教"写进了身份别名。因此它只能算内部核验，不能当作独立测试。为得到更可信的数字，项目另做了封存盲测：按规则重新写 20 条问法，写完立即记录文件哈希，只运行一次，不根据结果回改规则、口语映射或阈值。

首版在 16 条开发样例上从十个阈值中选取 0.21。首轮 36 题用于记录初版表现并定位错例，因此在第二轮并入开发范围。改进版增加口语改写、补充明确的范围拦截，并扩充身份别名。迭代代码和阈值选择使用前两批共 52 条样例，阈值选为 0.27。阈值选择优先比较流程成功数，其次比较范围外转介数，仍相同则选较高阈值。首位命中率只计算有目标规则的题，流程成功率覆盖全部题，同时检查实际输出是否有办理步骤、该规则所列网址或转介网址。

两轮盲测的检索结果分别是 11/20、12/20 和 14/20、14/20，与内部核验的 22/24、18/24 相比有明显落差。落差主要来自问法本身：内部核验与开发集同源，措辞接近规则里的检索短语；盲测用的是"拖几天""找不着""咋办"这类说法，词面重合低，多数落在阈值之下被转介。这提示此前的 75% 更接近"在熟悉问法上的表现"，而对新问法的覆盖需要单独统计。

## 4.1 结果解读与边界

分类器的优势来自规则表短语的弱标注，这让它见过了同一业务的多种说法；代价是把"范围外"也学成一类后，边界由样本决定，遇到没见过的范围外问法仍可能被归到某条规则上。第二轮盲测里两条范围外问法都被正确转介，但这只是两个样本，不足以说明边界稳固。检索方案则相反：阈值保守，代价是覆盖不足。

两条待改进的地方比较明确。一是概率未校准，无法据置信度做分级处理；二是一些常见说法仍未进入口语映射，例如"查归还记录""被预约了为什么续不了"，导致检索方案在盲测里过度转介。前者需要更多标注或校准方法，后者可以在不改动评估集的前提下补充词表，再用新的封存样本复核。

# 五、错例、演示与改进

内部核验阶段的错例集中在两类。第一类是范围误判：首版 T28 把"怎么预约靠窗的座位"路由到纸质图书预约，两种服务共用"预约"一词，而首版范围过滤只覆盖若干固定搭配；改进版把座位、打印、扫描等业务纳入范围检查，同类题 A21 得到正确转介。第二类是阈值边界：A16 已经找对了遗失规则，得分 0.269039 略低于 0.27，被转介；A10 询问借期延长网页，两种方法都把普通借期排在首位。这类错误说明阈值把"排序正确但分数偏低"和"排序错误"混在一起处理。

盲测阶段的错例更能说明问题。检索方案六条失败全部是转介，其中 L04"博士借一本书可以看多久"、L08"续借时提示被预约了是什么原因"、L11"把书弄丢了第一步做什么"都属于词面重合不足；L01"借纸质书必须用本人的证吗"得分 0.2076，离关键词阈值 0.21 只差 0.0024。分类器的三条错误各不相同：L05 把还书记录问题追问成校区，L08 把"续借失败"判成普通续借，L11 把遗失处理判成借书流程；L04 则因概率偏低被转介。前两条是相邻规则的边界问题，第三条是"丢书"与"借书"共享"书"字导致的特征混淆。

## 5.2 使用价值与边界

现有原型适合做办事前的快速导航。它将规则出处与行动清单同时呈现，并在材料不足时保留人工确认途径。身份与校区只保存于本次交互，程序不要求录入学号、密码或借阅清单。规则会随图书馆公告变化，延续使用前应更新规则快照。十条规则、少量短语和合成问法规模有限，盲测又只有 20 条，独立读者验证仍然需要补充。实时库存、借阅到期日及实际赔偿等以馆方系统和人员确认为准。

后续可请不同校区的读者分别通过官网和助手查询同类事项，比较是否找到正确出处、完成查询所需时间和点击次数。也可以在补足样本后重做概率校准，把"高置信直接答、中置信给候选、低置信转介"做成三级处理，并用新的封存样本检验。测试只记录匿名汇总结果。

# 七、运行复现与 AI 使用

[COMMANDS]

代码入口为 assistant.py，规则资料与实验标注在 data 目录。evaluate.py 导出内部核验的指标及逐题记录；evaluate_blind.py 在封存盲测集上比较三种路由方案，运行前会校验盲测文件的哈希；tests 包含正常及边界单元测试；demo 收录程序输出、演示图和一次完整追问的逐步回放。测量环境为 Python 3.14.6 和 scikit-learn 1.9.0。

[REPO]

分类器可用 python assistant.py --router classifier 试用，训练在启动时完成，只用本地标注文件。盲测结果可用 python evaluate_blind.py --blind data/blind_cases_v2.csv --manifest data/blind_manifest_v2.json --tag blind_v2 重放，输出与封存记录一并提交。
